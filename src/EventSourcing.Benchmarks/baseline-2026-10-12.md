# Compact all-provider baseline — SQL Server Express refresh (2026-10-23)

## Plan

Target: complete SQLite, SQL Server Express, and local PostgreSQL sequentially in under 10 minutes, including database preparation, warmup, verification, reporting, and cleanup. Runtime depends on the target instances.

| Parameter | Value |
|---|---|
| Providers | SQLite, SQL Server, PostgreSQL |
| Scenarios | global, tail, stream, write, mixed |
| Seeded history | 10,000 events |
| Payload | 1,024 ASCII Data bytes/event, excluding JSON overhead |
| Streams | 10 |
| Workers | 1 and 4; mixed uses matching reader/writer counts |
| Write batches | 2, 100, 1,000 events, including a real CommandProcessed marker |
| Operations | 10 per worker per repetition |
| Repetitions | 2, with a separate one-operation/worker warmup per workload |
| SQL Server transfer | auto: scalar, TVP, and staged bulk paths |

This is 18 workloads and 36 measured repetitions per provider, 108 measured repetitions in total. Two repetitions and short fixed-work groups keep the runtime budget small; tail percentiles and scaling are directional rather than precision estimates. Global reads cover 10,000 events, tail reads cover up to 1,000, and stream reads cover one seeded stream. Mixed groups may finish at different times.

Only runner-owned isolated databases are created and removed. Existing database contents and durability settings are retained. SQL Server targets the local `SQLEXPRESS` instance; PostgreSQL targets `localhost:5432`. Connection strings and credentials are not recorded here.

## Reproduction

From the repository root, with `EVENTSOURCING_BENCHMARK_SQLSERVER` and `EVENTSOURCING_BENCHMARK_POSTGRES` configured:

```powershell
dotnet build src/EventSourcing.Benchmarks -c Release --no-restore
dotnet run -c Release --no-build --project src/EventSourcing.Benchmarks -- --provider all --profile quick --scenarios global,tail,stream,write,mixed --workers 1,4 --batches 2,100,1000 --histories 10000 --payloads 1024 --streams 10 --operations 10 --repetitions 2 --command-batches --sql-transfer auto
```

Write operations/s means committed appends/s; events/s includes the completion markers. Read operations/s means complete enumerations/s (lower for large reads). Throughput uses group-active time. Counts verify persistence/enumeration, not input-order or commit-order guarantees.

## Execution results

This aggregate combines the SQLite and PostgreSQL measurements from 2026-10-12 with a SQL Server Express rerun from 2026-10-23. Each provider has 18 workloads and 36 measured repetitions. Both runs completed with zero operation failures and successful persisted/read count verification. The SQL Server Express Release build succeeded with zero warnings or errors.

### Environment and code state

- Host: Windows 10.0.26300, x64, 16 logical processors. The October 12 run used .NET 10.0.12; the October 23 SQL Server Express run used .NET 10.0.13.
- Git HEAD: the October 12 SQLite/PostgreSQL run used `fdb1ed0531e60789055a114cb9da7f29061e6dee`; the SQL Server Express run used `24b9b880f96c1f28a45968cc5e48f4563176c105`. The Express run's only reported working-tree modification was this baseline Markdown file.
- SQLite 3.53.3: file-backed, WAL, synchronous=2 (FULL), page size 4,096; provider command timeout 30 seconds, PRAGMA busy_timeout=0.
- SQL Server Express: local `SQLEXPRESS` instance, SQL Server 2025 RTM, 17.0.1000.7, Express Edition x64 on Windows 10.0.26300. Connected with integrated authentication and `TrustServerCertificate=True`. RCSI on, snapshot isolation OFF, read committed, SIMPLE recovery, delayed durability DISABLED.
- PostgreSQL 18.6: native Windows x64 server at localhost:5432; read committed, synchronous_commit=on, fsync=on, full_page_writes=on, wal_level=replica, max_connections=100.
- SQLite and PostgreSQL retain their October 12 measurements; SQL Server Express was rerun independently on October 23. These results describe the tested local targets, rather than an engine-only comparison.

### Artifacts, attempts, and cleanup

- SQLite/PostgreSQL source artifacts: `artifacts/benchmarks/20261012-065242-a3ef4f6a/`. SQL Server Express run artifacts: `artifacts/benchmarks/20261023-075040-92f618b3/`. Each contains the full results, summaries, and process-wide allocation report; artifacts are Git-ignored.
- The SQL Server Express runner-owned database was removed after the run; a server catalog query confirmed it was absent. Runner-owned databases from the October 12 run were also verified absent after execution.

### Observations

- At four writers, pure-write batch-100 throughput was 7,555 events/s for SQLite, 48,848 for SQL Server Express, and 101,794 for local PostgreSQL. Corresponding append rates were 75.552, 488.485, and 1,017.941 appends/s.
- Four-reader global replay throughput was 540,570 events/s for SQLite, 181,584 for SQL Server Express, and 496,775 for local PostgreSQL.
- SQLite write contention produced long outliers: maximum pure-write batch-1,000 latency at four writers was 1,315.585 ms. The corresponding maxima were 135.370 ms for SQL Server Express and 64.947 ms for PostgreSQL.
- Each aggregate has only 20 successful operations at one worker or 80 at four workers, per operation kind. Short runs and warm-cache effects limit precision; p99 is the maximum at these sample sizes. Mixed groups do not necessarily contend for their entire active interval. This establishes a new reference, with no before/after improvement claim.
